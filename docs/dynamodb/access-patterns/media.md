# Data Modal - Media
**DynamoDB** data modal for managing media in Sale Sync


## Folder

### Table Structure — DynamoDB Item Layout

| Key          | Index                   | Value Pattern                       | Purpose                                           |
| ------------ | ----------------------- | ----------------------------------- | ------------------------------------------------- |
| `PK`<br><br> | `main table`            | `WS#{workspace_id}#FOLDER`          | Partition key — scopes all items to a workspace   |
| `SK`         | `main table`            | `FOLDER#{folder_id}`                | Sort key for folder items                         |
| `GSI1PK`     | `folder-contents-index` | `FOLDER#{workspace_id}#{parent_id}` | Groups items by their parent folder               |
| `GSI1SK`     | `folder-contents-index` | `FOLDER#{name}`                     | Identifies item as a folder within the parent     |
| `GSI2PK`     | `path-index`            | `PATH#{workspace_id}`               | Groups all items by workspace for path queries    |
| `GSI2SK`     | `path-index`            | `{full/path/to/folder}`             | The full materialized path (e.g. `/docs/reports`) |
| `GSI3PK`     | `folder-name-index`     | `FOLDER#{workspace_id}#{parent_id}` | Groups folders by parent for name lookups         |
| `GSI3SK`     | `folder-name-index`     | `NAME#{folder_name}`                | Enables duplicate name check + name prefix search |

### Index Summary

| Index Name                          | Partition Key                                | Sort Key                      | What It Enables                                  |
| ----------------------------------- | -------------------------------------------- | ----------------------------- | ------------------------------------------------ |
| `main table`                        | `PK = WS#{workspace_id}#FOLDER`              | `SK = FOLDER#{folder_id}`     | `Direct get by ID`                               |
| `folder-contents-index`<br>`(GSI1)` | `GSI1PK = FOLDER#{workspace_id}#{parent_id}` | `GSI1SK = FOLDER#{name}`      | `List folders inside a parent`                   |
| `path-index` <br>`(GSI2)`           | `GSI2PK = PATH#{workspace_id}`               | `GSI2SK = {/full/path}`       | `Find descendants by path prefix`                |
| `folder-name-index` `(GSI3)`        | `GSI3PK = FOLDER#{workspace_id}#{parent_id}` | `GSI3SK = NAME#{folder_name}` | `Duplicate name prevention + name prefix search` |

## Media

### Table Structure — DynamoDB Item Layout

| Key      | Index                   | Value Pattern                       | Purpose                                                       |
| -------- | ----------------------- | ----------------------------------- | ------------------------------------------------------------- |
| `PK`     | `main table`            | `WS#{workspace_id}#PENDING#MEDIA`   | Partition key — pending media awaiting upload confirmation    |
| `PK`     | `main table`            | `WS#{workspace_id}#MEDIA`           | Partition key — confirmed/ready media                         |
| `SK`     | `main table`            | `MEDIA#{media_id}`                  | Sort key for media items                                      |
| `GSI1PK` | `folder-contents-index` | `FOLDER#{workspace_id}#{folder_id}` | Groups media by their parent folder                           |
| `GSI1SK` | `folder-contents-index` | `PENDING#MEDIA#{file_name}`         | Identifies item as pending media within the folder            |
| `GSI1SK` | `folder-contents-index` | `MEDIA#{file_name}`                 | Identifies item as media within the folder                    |
| `GSI2PK` | `path-index`            | `PATH#{workspace_id}`               | Groups all items by workspace for path queries                |
| `GSI2SK` | `path-index`            | `{full/path/to/file.ext}`           | The full materialized path (e.g. `/marketing/banner.png`)     |
| `TTL`    | `main table`            | `Unix timestamp (seconds)`          | Top-level TTL attribute — DynamoDB auto-deletes pending items |

### Index Summary

| Index Name                          | Partition Key                                | Sort Key                     | What It Enables                                               |
| ----------------------------------- | -------------------------------------------- | ---------------------------- | ------------------------------------------------------------- |
| `main table`                        | `PK = WS#{workspace_id}#MEDIA`               | `SK = MEDIA#{media_id}`      | Direct get by ID (ready media only)                           |
| `main table`                        | `PK = WS#{workspace_id}#PENDING#MEDIA`       | `SK = MEDIA#{media_id}`      | Direct get by ID (pending media only)                         |
| `folder-contents-index`<br>`(GSI1)` | `GSI1PK = FOLDER#{workspace_id}#{folder_id}` | `GSI1SK = MEDIA#{file_name}` | List media inside a folder                                    |
| `path-index`<br>`(GSI2)`            | `GSI2PK = PATH#{workspace_id}`               | `GSI2SK = {/full/path}`      | Find media by path prefix (used by folder descendant updates) |

### Key Design Notes

- **Two partitions** — media items live in two separate partitions: `#PENDING#MEDIA` for in-progress uploads and `#MEDIA` for confirmed ready items. Queries on `listMediaInFolder` never return pending items.
- **TTL on pending** — pending media records have a top-level `TTL` attribute (Unix timestamp). DynamoDB auto-deletes them after 24 hours if upload is never confirmed. No cleanup job needed.
- **Upload confirmation** — moving a record from `#PENDING#MEDIA` to `#MEDIA` is handled by a standalone Lambda (`media-s3-event/s3-event.ts`) attached to the S3 bucket, triggered on uploads under the `cdn/{workspace_id}/{media_id}/{filename}` key prefix (matching `s3_key` built by `createMedia`). It promotes the item via `GetCommand` (fetch the pending item) + `TransactWriteCommand` (`Put` the new `#MEDIA` item with `status: 'ready'`/`size`/`mime_type`/`updated_at` set and `TTL` stripped, `Delete` the old `#PENDING#MEDIA` item) — a conditional atomic swap, not a plain `UpdateCommand`, so a promote can't partially apply. `item_count` on the folder is incremented only on confirmation, not on `createMedia`. See [`docs/infra/README.md`](../../infra/README.md) for the S3 notification/IAM wiring.
- **`item_count` lives on folder** — `updateCount` in `media.service.ts` updates `data.item_count` on the **folder** item, not the media item. Media does not track its own count.
- **Controller passes folder object** — due to SAMJS service isolation, `MediaService` cannot call `FolderService` directly. The controller fetches the folder and passes it into `createMedia` and `moveMedia`.
- **Materialized paths** — each media item stores its full path (e.g. `/marketing/banner.png`). Updated automatically when parent folder is renamed or moved via `updateDescendantPaths` in `folder.service.ts`.
- **`updateCount` not fully atomic** — `SET + if_not_exists` is used instead of `ADD` because `ADD` does not support nested attributes inside `data`. See warning comments in code for details.
